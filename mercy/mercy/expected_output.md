# 期望的输出

我们的项目旨在开发一个基于区块链的捐赠追踪和自动拨款系统，以增强慈善捐赠的透明度和问责性。预期成果包括：

## 1. 去中心化捐赠追踪系统

基于Hyperledger Fabric构建的原型系统，能够以不可篡改和透明的方式记录捐赠交易。每笔交易，包括捐赠金额、受赠者和时间戳，将被安全地存储在区块链上，确保数据完整性并防止篡改。

### 1.1 交易数据结构表示

每笔捐赠交易都安全地存储在区块链上，其结构如下：

| 交易ID | 捐赠者ID | 金额（美元） | 项目ID | 时间戳 | 资金状态 | 项目状态 |
|--------|----------|--------------|--------|--------|----------|----------|
| TC001  | D112     | 100          | 00012  | 2025-03-06 10:15:30 | 完成     | 完成     |
| TC002  | D123     | 50           | 00017  | 2025-03-06 12:05:10 | 已取消   | 暂停     |
| TC003  | D162     | 200          | 00023  | 2025-03-06 14:20:45 | 80%已资助 | 进行中   |
| TC004  | D188     | 150          | 00085  | 2025-03-06 15:35:00 | 部分资助 | 已开始   |

每条记录包含一个唯一的交易ID、捐赠者信息、受赠者详情以及捐赠的状态（已完成、待处理等）。一对一的捐赠者与项目关系：每个项目由单一慈善组织资助，而单一捐赠者可以资助多个项目。

### 1.2 捐赠者注册数据结构

| 字段名称 | 数据类型 | 描述 | 是否必填 |
|----------|----------|------|----------|
| 捐赠者ID | 字符串（唯一） | 分配给区块链上每个捐赠者的唯一标识符（例如，D112） | 必填     |
| 姓名     | 字符串   | 捐赠者的全名（可选） | 可选     |
| 电子邮件 | 字符串   | 用于通知和沟通的电子邮件地址 | 必填     |
| 电话号码 | 字符串   | 捐赠者的联系电话（可选） | 可选     |
| 钱包地址 | 字符串   | 捐赠者的区块链钱包地址，用于追踪交易 | 必填     |
| KYC验证  | 布尔值   | 指示捐赠者是否已完成KYC验证（True/False） | 必填     |
| 偏好类别 | 列表[字符串] | 捐赠者感兴趣的捐赠类别（例如，["教育", "健康"]） | 可选     |
| 总捐赠金额（美元） | 浮点数 | 捐赠者已贡献的总金额（美元） | 必填     |
| 注册时间戳 | 日期时间 | 捐赠者注册的日期和时间 | 必填     |
| 状态     | 字符串   | 捐赠者账户状态（活跃、暂停、黑名单） | 可更新   |

为了将捐赠者注册整合到区块链系统中，应实施以下措施：

- **唯一性验证**：通过确保每个钱包地址和电子邮件的唯一性，防止重复注册。
- **KYC合规性**：标记为KYC验证 = False的捐赠者可能在完成验证之前有捐赠限制。
- **欺诈预防和黑名单机制**：被列入黑名单的捐赠者不能发起交易。任何可疑活动（例如，重复失败的交易或虚假身份）应触发审查流程。

### 1.4 关键功能和优势

- **不可篡改的记录**：每笔交易和状态更新都安全地存储在区块链上。
- **基于角色的访问控制**：只有授权的利益相关者（项目所有者和捐赠者）可以修改项目数据。
- **自动资金分配**：根据验证后的里程碑逐步释放资金。
- **欺诈预防**：标记可疑项目，冻结资金直至问题解决。
- **集成准备**：系统可以扩展以包括外部支付网关，以便在未来版本中使用。

## 2. 基于智能合约的资金分配

使用预定义的智能合约规则进行自动资金分配，确保只有在达到特定里程碑时才会释放资金。

### 项目状态更新规则

为确保资金流程的完整性，项目状态转换遵循严格的预定义规则：

| 当前状态 | 下一允许状态 | 触发条件 |
|----------|--------------|----------|
| 已注册   | 已开始       | 项目通过初步审核，资金锁定在资金池中 |
| 已开始   | 进行中       | 项目提交第一个里程碑报告并通过系统或人工审核 |
| 进行中   | 接近完成     | 项目目标完成80%，并提交最终交付物以供审核 |
| 任何状态 | 标记为审查   | 检测到可疑财务活动或报告违规行为 |
| 标记为审查 | 任何状态     | 违规行为确认；资金冻结，待进一步调查 |

如果没有发现违规行为，项目可以恢复到之前的状态并继续更新。

### 关键实施规则：

- 智能合约中的`verifyProgress()`函数确保符合更新条件。
- 只有项目所有者可以请求状态更新，而捐赠组织有权批准或拒绝请求。
- 不允许跳过状态（例如，项目不能从“已开始”直接跳到“已完成”）。
